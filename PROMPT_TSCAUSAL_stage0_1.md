# PROMPT TSCAUSAL stage 0.1 — to the executor

You work in the `TSCAUSAL` repository as the executor. The spec is `SPEC_TSCAUSAL_stage0.md`,
the calibration script is `causal_polytope_calib.py`, both already in the repository. Your task
in this stage: close Stage A and carry out Stage B. Do NOT run Stages C and D.

## Repository rules

**Rule 0.** No statement about someone else's work is written from memory. Every
external number, definition or formula is backed by a verbatim quotation from the
downloaded source in `SOURCES.md`, with the arXiv number and the equation number. If
the source could not be downloaded — you write "not confirmed" and do not use it.

**Preregistration.** Before the first Stage B run, create `PREREGISTRATION.md`:
your own predictions (number of vertices, number of facets, number of classes after
canonicalization, expected outcome), trigger criteria, tolerances. Compute the SHA-256,
commit it as a separate commit, put the hash into `RESULTS.md`. My prediction, which must
be entered there as a separate line labelled "architect's prediction": in the scenario
without settings there will be no new facet classes, everything will fit into the four
known inequalities.

**Reporting.** `RESULTS.md` is not written by hand, it is generated by the script
`scripts/make_results.py` from `results/json/`. Every run puts its own JSON there.

**Calibration of every estimator.** Any function that classifies or enumerates
something is first run on a case with a known answer. If a test cannot be failed —
it is vacuous and does not count.

## Stage A — gate

1. Run `causal_polytope_calib.py`. The result must be: 112 vertices,
   4 normalization equalities, GYNI = 1/2, LGYNI = 3/4. If it disagrees — stop,
   sort out the definition of the scenario.
2. Download Branciard, Araújo, Feix, Costa, Brukner, NJP 18, 013008 (2015),
   arXiv:1508.01704. Find, for the scenario "two inputs, two outputs, everything
   binary", the exact number of nontrivial facets and the number of equivalence
   classes. Compare with our 36 raw facets.
3. Independent cross-check of the tooling: enumerate the facets of the same input via `lrs`
   and via `pycddlib`; the lists must coincide as sets after reduction to integer
   coefficients. A discrepancy — stop.

Stage A gate: items 1 and 3 passed, item 2 either confirmed by a quotation, or
explicitly marked as unconfirmed.

## Stage B — the time-symmetric polytope

Scenario: two parties, each with a binary income and a binary outcome, no settings
(`N_α = N_β = 1`), the pre- and postselection variables marginalized.
The coordinates are `p(a, b, x, y)`, 16 of them.

1. Write out from arXiv:2406.18489 the double-causality conditions and the constraints
   on causally separable correlations for the orders A ≼ B and B ≼ A (equations 3–6),
   with verbatim quotations in `SOURCES.md`. Do not rewrite them from memory.
2. Generate the deterministic vertices of both orders, take the union.
   Check that the known inequalities attain on this set exactly their causal
   maxima: GYNI 1/2, reversed GYNI 1/2, LGYNI 3/4, reversed
   LGYNI 3/4. This is a gate: if even one gives something else — it is an error in
   the definition of the vertices, not a discovery.
3. Enumerate the facets in exact arithmetic.
4. **Canonicalization.** Project every facet onto the affine hull of the
   polytope, reduce it to integer coefficients by dividing by the GCD, take the
   lexicographic minimum over the symmetry group of the scenario: exchange of parties,
   reversal of the direction of time (a ↔ x, b ↔ y), local relabelings of values.
   Only after that count the classes.
   Mandatory anti-vacuum test of the group: apply each generator to a known
   inequality and check that the orbit is nontrivial and that the image
   remains a valid inequality for the same set of vertices. If a generator
   acts as the identity — it is not implemented, rather than "the symmetry coincided".
5. Match the classes against the four known ones. The result goes to `results/json/`.

Outcomes fixed in advance:
- all classes are known → question 1 is closed negatively in this scenario, this is a
  publishable result, not a failure;
- there is a class not reducible to the known ones and not mapped to itself under
  reversal of the direction of time → a candidate for a new causal inequality, then
  Stage C, but it is launched not by you, by me, with a separate prompt;
- the enumeration did not finish → record the ceiling as a number (vertices, hours,
  memory) and do not pass off a partial search as a complete one.

## What not to do

- Do not run Stages C and D: they need an explicitly restricted class of processes,
  otherwise the test is vacuous (the full class with postselection attains the
  algebraic maximum of any causal inequality).
- Do not declare anything new without a literature check: has anyone enumerated the
  facets of the time-symmetric causal polytope after June 2024.
- Do not tailor the definition of the scenario to a pretty answer. A negative outcome is
  an admissible and expected result.
